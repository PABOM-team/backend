# API 구현

Spring Boot API를 신규 구현하거나 수정할 때 사용한다.

1. 수정 전 Controller, Service, DTO, Security, Domain, Repository의 기존 패턴을 확인한다.
2. 누락된 요청 필드, 비즈니스 규칙, 엔드포인트를 임의로 만들지 말고 불명확한 부분을 보고한다.
3. 구현 전에 HTTP 메서드·경로, 인증, 요청 검증, 응답 스키마, 에러 코드, 부수 효과를 정리한다.
4. 기존 공통 예외 처리와 인증을 재사용한다. 리소스 소유권을 검증하고 다른 사용자의 데이터를 노출하지 않는다.
5. 관련 데이터 변경은 적절한 트랜잭션으로 묶고, 요구사항에 있는 멱등성 및 동시성 제어를 적용한다.
6. 기존 API와의 호환성을 유지하며 작업 범위 밖 기능은 구현하지 않는다.
7. 테스트와 Swagger 예시를 작성하고, 변경 파일·요구사항 차이·테스트 결과를 보고한다.

PABOM 주의: 명시적으로 요청된 경우 관리 일정 없이 수동 기록을 생성할 수 있어야 한다(`routineId`, `routineUpdated`는 null 가능). 관리 기준표 값은 임의로 만들지 않는다.
