# 데이터베이스 마이그레이션

스키마, Entity, 인덱스 또는 데이터 보관·삭제 정책을 변경할 때 사용한다.

1. 변경 전에 Flyway 버전, Entity 매핑, 제약조건, 인덱스, 데이터 생명주기를 확인한다.
2. 적용된 마이그레이션은 수정하지 않고 **새 버전의 Flyway 마이그레이션**을 추가한다.
3. Nullable, Unique, 외래 키, 인덱스, 기존 데이터 채우기 및 기본값 정책을 명확히 한다.
4. 기존 데이터에 안전하며 프로젝트의 MySQL 설정과 호환되는지 검증한다.
5. 부모·자식 데이터, 정정 이력, 파일 메타데이터의 삭제 순서와 FK 관계를 확인한다.
6. 기록 개별 Soft Delete, 회원 탈퇴 시 물리 삭제, 향후 개체 삭제는 서로 다른 생명주기 정책으로 취급한다.
7. 가능한 경우 마이그레이션·Repository 테스트를 추가하고 운영 위험과 롤백 방안을 설명한다.
